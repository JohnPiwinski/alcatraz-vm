AlcatrazVM setup book

AlcatrazVM is a four-role Firecracker/KVM isolation layout for VibeKanban, Codex, Git, and Build. This book is a compact browser-readable companion to SECURE_AI_VM_ARCHITECTURE.md.

Important: the VM boots a verified Linux kernel and minimal ext4 rootfs. It does not boot an ISO. Podman builds the userland; it does not replace the kernel.

1. Start with a capable host

Use Linux x86-64 with readable /dev/kvm, Podman, jq, curl, debugfs, mkfs.ext4, C, Git, and Cargo. The production Jailer also needs root or equivalent mount-namespace capability. The existing ms container is deliberately not used as a base image.

test -r /dev/kvm
podman --version
/home/jpwin/firecracker/firecracker-v1.16.1-x86_64 --version
/home/jpwin/firecracker/jailer-v1.16.1-x86_64 --version

2. Build minimal role images

Build each clean, digest-pinned Debian role with Podman, convert its tar export to ext4, inject only reviewed fixed executors, and seal the final image. Use scripts/build-sealed-role-rootfs-podman for the one-step version.

mkdir -p .image-build/roles
cargo build --bins
scripts/build-sealed-role-rootfs-podman build \
  "$PWD/.image-build/roles/alcatraz-build-rootfs.ext4" \
  "$PWD/.image-build/debian-vmlinux"
scripts/verify-image-contract build \
  "$PWD/.image-build/roles/alcatraz-build-rootfs.ext4" \
  "$PWD/.image-build/debian-vmlinux"

Repeat for vibe-kanban, codex, and git. The Vibe builder warms the pinned VibeKanban runtime and confirms its internal port 3000 before export.

3. Verify before trusting a boot

scripts/verify-no-pci
scripts/verify-role-boundaries
scripts/integration-smoke

The suite checks bounded typed protocol behavior, MMIO-only Firecracker configuration, role-boundary negative checks, real KVM boots, two-VM vsock routing, VibeKanban host HTTP 200, Vibe↔Codex records, Git SSH-key injection and clone, Cargo, Git, and reset. A successful boot by itself is not an isolation proof.

4. Replace VibeKanban with the emulator

vibe-codex-emulator performs the fixed handshake and sends only submit-task, status, or operator-review records.

cargo build --bin vibe-codex-emulator
vibe-codex-emulator --socket /var/lib/alcatraz/run/codex.vsock \
  submit-task 'Implement the sample project'
scripts/vibe-emulator-smoke

5. Run Codex with a ChatGPT subscription

On the machine or VM that owns the second Codex process, run codex login and choose Sign in with ChatGPT. Keep its credential store private to Codex; never copy it into VibeKanban, Git, or Build.

codex login
codex login status
scripts/codex-subscriber-smoke

For unattended service use, an approved API/service identity is required; a ChatGPT subscription is not an API key.

The end-to-end sample defaults to the authenticated Codex CLI. Its fixed provider allowlist also permits ALCATRAZ_AGENT=opencode when installed; unknown providers are rejected.

6. Operate the jailed launcher

scripts/alcatraz-vm start build config/firecracker/build.json
scripts/alcatraz-vm status build
scripts/alcatraz-vm logs build
scripts/alcatraz-vm stop build
scripts/alcatraz-vm reset build

The launcher accepts only fixed roles and matching repository configs. It verifies sealed image sidecars, stages a private rootfs, and invokes Jailer with a per-role chroot, UID/GID drop, PID namespace, and resource limit. Unjailed mode requires both ALCATRAZ_LAUNCH_MODE=unjailed and ALCATRAZ_UNSAFE_UNJAILED=1, and is for development only.

Build has no network device or default route. Git keys remain in the Git VM. VibeKanban has no Codex key, Git key, host mount, or direct Git/Build channel.

7. Troubleshoot

  • Jailer EPERM: run on a host/container with mount namespace capability; do not silently switch to unjailed production.
  • Vibe HTTP failure: inspect serial.log for the Vibe server and fixed port-3000 proxy markers, then retry the host UDS path.
  • Image contract failure: a kernel/rootfs or sidecar was changed after sealing; rebuild and seal the final artifact.
  • Cargo failure: confirm the fixed executor is current, Cargo is at /usr/bin/cargo, and the workspace is inside the Build root.

For the complete command reference, provenance details, protocol policy, and recovery procedure, read SETUP_TUTORIAL.md and the architecture specification.
